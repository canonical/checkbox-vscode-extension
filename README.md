# Checkbox Units for VS Code

A VS Code extension with a language server for Checkbox unit files: PXU
(`*.pxu`) and YAML (`units/**/*.yaml`). The extension provides:

- **Go to definition** on unit references. Supported fields are `depends`,
  `after`, `before`, `salvages`, `requires`, `imports`, `category_id`,
  `template-resource`, `template-imports`, `template-filter`, `include`,
  `exclude`, `mandatory_include`, `bootstrap_include`, `setup_include`,
  `nested_part` and `category-overrides`. For a regular expression, go to
  definition lists every unit that the pattern matches.
- **Go to definition** on a manifest attribute in `requires` or
  `template-filter`, such as `has_bt_adapter` in
  `manifest.has_bt_adapter == 'True'`. It lists the `manifest entry` units
  whose `resource-key` (by default, the partial id) matches, in any provider.
  This works when `manifest` resolves to `com.canonical.plainbox::manifest`,
  usually through `imports`. Attributes with template placeholders, such as
  `need_{type}_test`, list every entry they can match.
- **Go to definition** on the namespace in an `imports` line, such as
  `com.canonical.plainbox` in `from com.canonical.plainbox import manifest`.
  It lists the `namespace` or `name` argument in the `manage.py` of every
  provider with that namespace. For the built-in plainbox providers, it lists
  their definitions in `plainbox/impl/providers/special.py`.
- **Completion** in test plan units: job and template ids in `include`, and
  test plan ids in `nested_part`. Ids in the test plan's own namespace are
  suggested as partial ids; type `namespace::` to get qualified ids. In
  `include`, only the pattern is completed, not the `field=value` overrides.
  In YAML files, VS Code does not show suggestions automatically inside
  strings, which includes plain YAML values. Press Ctrl+Space, or set
  `"[yaml]": {"editor.quickSuggestions": {"strings": "on"}}`.
- **Hover** on a unit reference to show the id and `summary` of the unit it
  points to. For a regular expression, the hover lists up to 10 matching
  units.
- **Reference diagnostics** while you type:
  - **Error**: a unit id that does not exist, a namespace that no provider in
    the workspace defines, or a reference to the wrong kind of unit. Examples
    of the wrong kind are a `requires` reference to a job that is not a
    resource job, a `category_id` that is not a category, and a
    `setup_include` or `bootstrap_include` entry that is not automated.
  - **Error**: a syntax error that hides references, such as a malformed
    `imports` line or include line, or an invalid regular expression.
  - **Warning**: an include pattern that matches no unit.

The extension indexes every provider in the workspace. A provider is a
directory with a `manage.py`, and its units are the files under `units/` or
`jobs/`.

The extension knows about implicit ids:

- `siblings` entries;
- ids generated by the `also-after-suspend` and `also-after-suspend-manual`
  flags;
- `template-id` values.

An id that matches a template `id` (for example `foo_{name}`) counts as
resolved, because template instances only exist at runtime. Template fields
with `{placeholders}` or Jinja2 syntax are not checked.

## Build and run

```bash
npm ci
npm run compile
```

To try it, open this directory in VS Code and press F5 (**Run extension**).
This opens a new window on `../checkbox`, the Checkbox checkout next to this
one.

To install it, build a `.vsix` file with `npm run package` and run
`code --install-extension vscode-checkbox-*.vsix`. Then open a Checkbox
checkout in VS Code.

## Settings

- `checkbox.additionalProviderPaths` lists more directories to scan for
  providers. Use it when the workspace does not contain a provider that
  another provider references. For example, units from the
  `com.canonical.plainbox` namespace live in a checkbox-ng checkout.

## Tests

```bash
npm run lint
npm test
```

Some tests run against a Checkbox checkout. By default they use
`../checkbox`; set `CHECKBOX_REPO` to use another path. These tests are:

- `test/repo.test.ts`, which checks that no false errors are reported on the
  providers in the checkout.
- `test/parity.test.ts`, which compares the TypeScript parsing with plainbox
  itself. It uses `scripts/dump_units.py`, which loads every provider in the
  checkout through checkbox-ng and dumps unit ids and references. Set
  `CHECKBOX_PYTHON` to a Python interpreter that can import plainbox, for
  example `../checkbox/checkbox-ng/venv/bin/python`.

```bash
CHECKBOX_PYTHON=../checkbox/checkbox-ng/venv/bin/python REQUIRE_PARITY=1 npm test
```

Without a checkout or an interpreter these tests are skipped, unless
`REQUIRE_PARITY=1` is set. CI sets it, tests against the `main` branch of
canonical/checkbox, and also runs daily so that upstream parser changes that
break parity are caught.

## Limitations

- The extension checks references only. It does not validate other fields.
- Diagnostics are published only for open files.
- Matching ids to templates is a heuristic. It prefers missing an error over
  reporting a false one.
